## Author workflow

1. Open a video project and Lesson guide. Import a Godot scene journal or a
   normalized application capture through **Application capture observations**.
2. Optionally expand **Associate recording times**. Explicitly choose a recording
   source and one uninterrupted recording interval from existing project metadata.
   No source/interval is selected automatically. If metadata is unavailable, ordinary
   drafting and manual media attachment still work.
3. After reviewing footage, enter matching capture and recording start/end times
   in seconds (up to three decimals), then **Add range**. Add separate ranges for
   pauses/gaps; each range must stay inside one interval. Invalid additions retain
   the valid current ranges. Editing pending fields does not silently change them.
4. Select observations and **Add selected observations as draft steps**. Only selected
   mapped observations receive a separate authored timing link. Gap/terminal
   observations still become drafts with their original independent evidence.
5. Save the lesson normally. The original observation clock stays `unmapped` and
   its original time/payload are preserved. A step shows its manual recording time;
   **Remove manual timing link** removes only that annotation. Attaching/exporting
   media still uses the existing explicit selection/grant/content-identity workflow.

Current calibration is temporary; selecting a different source, replacing capture
or recording metadata, or clearing it affects future drafts. Already-added step
annotations stay until explicitly removed. Saved lessons reopen offline without
Godot or live adapters. This slice does not reopen a full editable calibration plan
from a saved lesson; it retains only selected per-observation bindings and spans.

## Semantics and privacy

- Timing links store version/method, selected source asset ID, application
  adapter/instance/session/scope, content fingerprints, recording session/control
  clock, original application time, integer recording time and the single manual
  span used. They do not copy the full baseline or unselected observations/spans.
- The schema checks each annotation's bounds and interpolation rule and ties it
  back to its parent evidence identity/time. These are authored annotations and
  content references, not authenticated producer history or media-read authority.
- Existing evidence provenance stays observed for the captured state; the timing
  method is explicitly manual. No video range, JPEG, media selection or source-file
  grant is generated by calibration. Current media must be reviewed before use.
- Source/lesson changes during asynchronous creation invalidate the result instead
  of replacing newer work. Closing the journal cancels pending application and
  re-enables import. Source clock changes clear the calibration. Batches avoid
  per-row full-capture hashing.
- **L1 disposition:** exact `durationMs` observations intentionally remain unmapped
  under half-open ranges, now with explicit `end-of-capture` reason and visible
  guidance. They are not dropped from drafts.
- **L2 disposition:** recording positions are floored and clamped inside the chosen
  span before persistence. They cannot round onto the next pause/interval boundary.
  The same integer rule is checked again when reopening a stored annotation.

Only the final lesson-save IPC method is stubbed to retain its argument; no
production components or timing math are substituted.

**12 browser checks pass**: four observations, two distinct manually calibrated
ranges, integer 1200/5600ms bindings, selected source identity, unmapped raw clocks,
no automatic media selection, no baseline copied, link removal preserving raw
observations, Windows browser identity and no uncaught browser errors. Raw saved
lesson JSON from both saves and a screenshot are retained.

session ended; its failed attempt/logs are retained. The successful run kept that
session alive. The fixture server was stopped only after matching its PID/command
path; the tunnel was closed and no Edge processes using the unique temporary test
profile remained. No user browser profile/process, VM policy or real project changed.

This is real Windows browser component coverage with **synthetic capture/control
clock data**, not a packaged Windows Electron app, native file picker, physical
